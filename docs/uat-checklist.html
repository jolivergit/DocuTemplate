Before you start

  • Agree with the app operator which app/environment and accounts to test. Record the actual address you opened; a preview is not proof that a published app or its database is ready.
  • Use two approved practice firms, Firm A and Firm B, and fictional names beginning with UAT, your initials and the date/time. Reuse those names consistently and avoid duplicate firms on retries.
  • Use one consenting Owner test account and a second consenting coworker account. The Owner needs access to both practice firms; the coworker joins Firm A as a Member and can own their own separate personal workspace. Do not share passwords.
  • For Google cases, use test templates containing fictional information. Keep an untouched copy to compare afterward. Use a genuinely authorized Google account; the app does not bypass Google sharing or copying restrictions.
  • This is real application storage, not a simulation. New firms cannot currently be archived/deleted through the UI. Generated Google Docs are real copies; statuses and deletions change real records. Never use live customer billing as disposable data, send test documents to clients, or revoke another person's Google access.
  • Save existing work before starting. There is no general trash/restore or saved Doc Builder draft. Use a disposable note or field for any deliberate unsaved-edit or deletion check.
  • Write Pass, Fail, Blocked or Not run in each Result cell and add the actual outcome. Do not mark a blocked Google case passed just because the app says Connected.

Sign-in, firms and safe switching

Project through proposal and invoice

Use Firm A for this sequence. Reuse one fictional project, for example UAT Maple Street Renovation, a $10,000 Fixed Schematic Design / Interior Design proposal, 2 hours at $100/hr and $20 Parking. Keep Additional Services unsigned until after the first invoice arithmetic check.

IDWhat to doExpected outcomeResult / notes
P1As Owner create a fictional company and contact, link them, and create the practice Lead using those address-book entries. Edit and save a harmless project detail; search/filter for it and inspect Overview.Records persist and linked details are visible. Suggested company roles do not require entering duplicate address-book companies.Not run
P2Create the $10,000 Standard proposal. Reopen it, review phases/consultants/Fixed versus Hourly, then record fictional approval with Mark as Signed.The proposal retains its fee breakdown. Signing the Standard proposal makes the project Active Project and shows Time & Expenses and Invoices. No email or electronic signature is sent.Not run

Entries are not billed twice merely because they appear in the project list. Review attached entries carefully before changing them.Not run
P4Create the first invoice at cumulative 25% complete. Attach the existing two entries; do not retype them as new entries.With no other billing/charges, fixed earned and current fee are $2,500, Hours $200, Parking $20, total $2,720. Included entries gain an invoice badge and no longer appear as Unattached.Not run
P5On this practice invoice only, simulate sending and payment with Mark as Sent and Mark as Paid. Inspect Dashboard summaries. Start a later invoice at 50% complete and review before saving.Statuses are recordkeeping, not email or payment processing. Totals follow access/statuses. P7Check project lists, company/contact lists, Dashboard totals and the practice project link while switching between Firms A and B.Firm A's records do not appear in Firm B. Owning both firms does not merge their business records. Personal content library/contact values may remain available because they are personal, not firm-shared.Not run

Documents and Google recovery

Prepare a test Google Doc containing {{firm_name}}, {{project_name}}, {{proposal_name}}, {{proposal_total}} and optionally <<introduction>>. Use separate prepared templates for invoices and consultant contracts. Never post authorization tokens, API keys, callback/request URLs or invitation links in a bug report.

IDWhat to doExpected outcomeResult / notes
G1From the practice proposal choose Load to Doc Builder. Load Template; Connect Google if requested, using the same account, then Pick a Google Docs template.Connecting and choosing are separate steps. Selected-file access is requested, the chosen template's real name/tags load, and the app does not need account-wide Drive/Docs permission.Not run
G2Map every required tag to the loaded values, including any content tag. Generate with a distinctive UAT document name, open Google Docs and compare with the untouched source. Reopen the proposal.A new copy contains the expected firm/project/fee and mapped content, source remains unchanged, and the proposal shows its saved document link after confirmation. No client email is sent.Not run
G3With a working template/mappings, reopen template selection and cancel Google's chooser. Try Choose in separate window, then close it without selecting. Finally select a template there.Cancellation leaves the current template/choices intact. A completed separate-window selection returns to the original page and loads tags. Deliberately choosing a different template can replace working mappings.Not run
G4If the chooser fails inside the embedded preview, use Choose in separate window. If the browser blocks it, allow popups for the app and retry. Use Cancel chooser if an opening attempt is stuck.The app offers recovery without refreshing away working data or expanding Google scopes. If setup is missing, record Blocked and the visible message; Connected alone is insufficient.Not run
G5If some chooser thumbnails are blank, identify the file by name or switch Google's view to its filename list, then select it.Blank thumbnails are distinguished from absent files. A successful tag load proves more than the preview image; no broader permissions are needed just to show pictures.Not run
G6As the consenting test user, cancel or decline optional Google consent. Try a disposable template the account cannot access, if the operator has safely prepared one.No silent permission escalation, unwanted document or lost original mapping. Access failures are recoverable and do not expose another account's file data. Do not change live sharing settings to manufacture this case.Not run
G7Generate the practice invoice from its own Generate Doc → Generate & Save flow using a correctly tagged invoice template.Invoice totals, firm/client data and line items match the saved invoice; View Doc opens its linked copy. Unsupported/unmatched tags require review and may be blank; this flow is not Doc Builder's interactive mapper.Not run

If testing an older broad Google grant, follow the operator guide and obtain the account holder's consent before removing app access. Revocation can interrupt other sessions. Do not revoke a shared production grant as a routine UAT step.

Coworker access and differing roles

Use a consenting coworker's actual test Google account in a separate browser/profile so both sessions can remain open. Choose a project as assigned and create a second disposable unassigned practice project. Only share links to those approved test records.

IDWhat to doExpected outcomeResult / notes
R1Owner opens Firm A → Settings → Team, creates an email-bound link, and manually shares it. Coworker opens it with that verified Google account and accepts. Reuse the consumed link; test revoking another unused practice link.No automatic email. Accepted membership is Member. Used/revoked links fail. A link for another email cannot be accepted with the wrong Google account. Seven-day expiry should be recorded Blocked/Not run unless a safely prepared expired link is available.Not run
R2Before assignments, coworker selects Firm A and checks projects, Dashboard/search and the unassigned practice project's direct link.No project access is granted merely by membership. Unassigned records/details/totals remain hidden or denied, including when opening a known test URL.Not run
R3Owner selects the coworker in the assigned project's Project access area. Coworker returns to that project and works on its proposal/time/notes as appropriate.Only assigned work and its financial information become accessible. Owners need no assignment checkbox; Members cannot manage the team, change firm business details or delete projects/proposals/invoices.Not run
R4Coworker checks Owner access in their own separate workspace, then returns to Firm A as Member. Try the unassigned Firm A link again.Roles remain firm-specific. Ownership elsewhere does not reveal unassigned Firm A records or grant Owner controls there.Not run
R5Coworker creates a disposable project as a Member in Firm A.The project is automatically assigned to its creator and remains in Firm A, not the creator's personally owned workspace.Not run
R6At the end, Owner unassigns the practice project and tests removing the consenting coworker from Firm A. Separately try demoting/removing the last Owner without confirming any unrelated change.Next protected requests are denied after revocation; screens may refresh on focus or within 15 seconds. The last Owner is protected. Existing independent Google sharing is unchanged and downloaded copies cannot be recalled.Not run

Test result and bug report

If you see another firm's or person's unauthorized data, stop testing that path, avoid copying the content and record a minimal redacted report. For other failures, keep the entered values and current page where possible; do not repeatedly generate documents or delete records to try to fix it.
