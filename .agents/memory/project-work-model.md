---
name: Project work model
description: User's product definition for shared project phases, proposal documents, and task notes.
---

Project and proposal phases are the same thing. They are associated with fees, but fees are not their only purpose. Proposals are documents, and the customer does not want multiple entries of the same data.

**Why:** The user corrected a plan that separated execution phases from proposal phases and required copying them.

**How to apply:** Plan shared project information and phases reused by tasks and proposal preparation, not separate lists or manual copy/re-entry workflows.

Users should be able to add ad-hoc phases as well.

**Why:** The user explicitly requested ad-hoc phases.

**How to apply:** Support custom project phases without requiring predefined names, a fee, or an existing proposal; reuse the same phase for tasks and any later proposal inclusion.

The user does not need the current standalone project notes saved; replace them with task notes.

**Why:** The user explicitly rejected retaining the existing notes as history.

**How to apply:** Do not add a legacy-notes archive or automatic task conversion. Treat actual legacy-note removal as a destructive rollout step, not permission to delete data during planning or modify production without authorization.
